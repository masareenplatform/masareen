## Social-service (the new backend)

Location: `backend/social/posts-service/`  (NOTE: directory name is `posts-service`,
the combined monolith already expected `("ms_posts","social/posts-service")` in its
SERVICES list — do NOT rename back to `social_service`).

Files:
- `src/main.py` — `create_app` + `include_router(router, prefix="/api/v1")`, `on_startup=[init_db]`
- `src/db.py` — async engine. **Uses the SHARED `Base`** (`shared.base_repository.db.Base`)
  so the combined monolith's `Base.metadata.create_all` provisions posts/likes/bookmarks
  tables on the one shared DB. `DATABASE_URL` env is honored (Postgres in combined),
  falling back to local SQLite (`social.db`) for standalone dev.
- `src/orm.py` — `PostORM`, `LikeORM`, `BookmarkORM`
- `src/service.py` — ranking (mirrors web `rankScore`), CRUD, like/comment/save
- `src/schemas.py`, `src/security.py` (JWT via `shared.middleware.make_auth_dependency`)
- `src/seed.py` — demo posts (runs only in standalone `init_db`, not in combined)
- `src/api/__init__.py` — router, prefix `/posts`

Endpoints (all require Bearer JWT; envelope `{success,data}`):
`GET/POST /api/v1/posts`, `GET /api/v1/posts/saved`, `GET /api/v1/posts/{id}`,
`POST /api/v1/posts/{id}/like`, `/{id}/comment`, `/{id}/save`.
Returns camelCase shapes the web `PostCard` expects (`comments` is an **array**).

## How to test the social-service

From `backend/` with the venv (`.venv/Scripts/python.exe`):
```python
import sys; sys.path.insert(0, ".")
from social.posts_service.src.main import app   # standalone package name
# OR via combined registration: register("ms_posts","social/posts-service"); import ms_posts.src.main
from fastapi.testclient import TestClient
from shared.middleware import create_access_token, TokenPayload
tok = create_access_token(TokenPayload(sub="u1", email="a@b.com", role="Individual"),
                          secret="change-me-in-production")
hdr = {"Authorization": f"Bearer {tok}"}
with TestClient(app) as c:
    c.get("/api/v1/posts", headers=hdr)            # 200, seeded posts
    r = c.post("/api/v1/posts", headers=hdr, json={"text":"hi","kind":"story"})
    pid = r.json()["data"]["id"]
    c.post(f"/api/v1/posts/{pid}/like", headers=hdr)
    c.post(f"/api/v1/posts/{pid}/save", headers=hdr)
    c.get("/api/v1/posts/saved", headers=hdr)       # includes pid
```
Gateway (`backend/gateway/src/main.py`) now has `"social"` in SERVICE_REGISTRY and
`"/api/v1/posts": "social"` in ROUTE_MAP.

## Cautions / gotchas for next agent

- The combined monolith imports every service; `ms_posts` is included automatically
  because the directory now exists at the path `combined/main.py` already listed.
  If you add NEW tables, keep them on the **shared `Base`** (never a private one) or
  the combined `create_all` won't provision them.
- `social.db` (SQLite) is created in CWD when the service runs standalone without
  `DATABASE_URL`. It is git-ignored-ish; safe to delete.
- Web `postService.list()` is intentionally still synchronous (callers rely on it);
  backend hydration is a fire-and-forget background sync, not an await.
- `follow`/`is-following`/`suggested`/`notifications` already exist in
  `identity-service` / `notification-service`; only posts+bookmarks were missing.

## 3. How to REBUILD the APK (only if app code changes)
- Memory: 16 GB total. With emulator + Docker + backend running, ~3 GB free →
  Gradle OOMs. STOP THE EMULATOR during the build (`adb emu kill`), build, then
  relaunch + reinstall.
- `flutter build apk --release` from apps/mobile. If the flutter wrapper says
  "Gradle build failed to produce an .apk file", run
  `android\gradlew.bat assembleRelease` directly — it BUILDS SUCCESSFULLY.
- `android/gradle.properties` was tuned for this box: daemon=false,
  -Xmx1024m, -XX:MaxMetaspaceSize=256m. Revert if more RAM is available.
