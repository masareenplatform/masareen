# MASAREN, Alpha Deployment Guide

This document covers running the **MASAREN** alpha: 36 backend microservices behind a
single API gateway, plus the **Web**, **Admin**, and **Mobile (Android)** frontends.

> Status: backend is free of mock/fake data, external integrations (Stripe, Vodafone
> Cash, FCM, CrewAI) are **wired but disabled by default** and fail *honestly*
> (HTTP 501 / `false`) rather than fabricating success. See "Honest fallbacks" below.

---

## 1. Prerequisites

| Component        | Version            | Notes                                       |
|------------------|--------------------|---------------------------------------------|
| Docker + Compose | latest             | Runs the full backend + frontends.          |
| Node.js          | ≥ 18 (20 recommended) | For building the web/admin apps locally.  |
| Flutter SDK      | ≥ 3.16             | **Only** needed to build the Android APK.   |
| Java (JDK)       | 17                 | Required by the Flutter/Android Gradle build.|

## 2. Backend + Web + Admin (Docker Compose)

```bash
# 1. Configure secrets (copy and edit)
cp .env.example .env
#   at minimum set JWT_SECRET to a long random string

# 2. Bring everything up
docker compose up --build
```

Entry points once healthy:

| Service | URL |
|---------|-----|
| API gateway (BFF + all microservices) | http://localhost:8080 |
| Web app (volunteers / organisations) | http://localhost:3000 |
| Admin app (HITL verification + dashboards) | http://localhost:3001 |
| Gateway OpenAPI docs | http://localhost:8080/docs |

The gateway mounts every service under `/api/v1` and adds two composed BFF endpoints:
- `GET /api/v1/bff/dashboard`, cross-service platform snapshot
- `GET /api/v1/bff/leaderboard`, top impact contributors

### Admin / HITL

1. Open http://localhost:3001 and sign in with an account that has `role = ADMIN`
   (or `SUPER_ADMIN`).
2. Go to **Verification Queue** → each pending item maps to
   `GET /audit/review/pending`. **Approve / Reject** calls
   `PATCH /audit/review/{id}/resolve` with `verdict`, `comments`, `admin_id`.
3. Items resolved as `APPROVED` flow into the verification pipeline
   (evidence → impact score → org score).

## 3. Mobile (Android)

The `apps/mobile` Flutter project targets Android only. The `android/` folder is a
standard Flutter wrapper, **but the Gradle wrapper jar is generated by Flutter**, so
run this once to materialise it:

```bash
cd apps/mobile
flutter pub get
flutter create --platforms=android .     # regenerates android/gradle wrapper + boilerplate

# Point the app at your gateway (emulator uses 10.0.2.2 for host loopback):
flutter build apk --release \
  --dart-define=API_BASE_URL=http://10.0.2.2:8080/api/v1

# Install on a connected device/emulator:
flutter install
```

- Release APK: `apps/mobile/build/app/outputs/flutter-apk/app-release.apk`
- For a physical device on the same LAN, use your machine's LAN IP instead of
  `10.0.2.2`, e.g. `http://192.168.1.20:8080/api/v1`.
- `flutter analyze` should be run to confirm the local plugin surface (camera,
  geolocator, flutter_map) before store submission.

### Push notifications

Firebase Cloud Messaging is **not** wired into the build (it requires a
`google-services.json` from a real Firebase project). The app uses
`flutter_local_notifications` for local delivery. To enable FCM: add
`firebase_messaging` back to `pubspec.yaml`, run `flutterfire configure`, and implement
the `ApiService` push registration hook.

## 4. Honest fallbacks (no fabricated data)

| Integration | When unconfigured | When configured |
|-------------|-------------------|-----------------|
| Stripe payments | `POST /payments/psp/capture` → **501**; ledger records locally | Real PaymentIntents; marked `SETTLED` only on Stripe `succeeded` |
| Vodafone Cash | Raises `PspNotConfiguredError` | Requires provider contract + creds |
| FCM push | `send()` returns `False` | FCM HTTP v1 (service-account OAuth) |
| CrewAI chat agents | Gateway still proxies `/chat`; agent orchestration 503s without `CREWAI_BROKER_URL` | Routed to broker |

No test doubles, no demo data, and no hardcoded "success" responses are shipped.

## 5. Common env vars

See `.env.example`. The important ones:

- `JWT_SECRET`, **required**, must match across gateway + all services.
- `STRIPE_SECRET_KEY`, enables real payments.
- `FCM_SERVICE_ACCOUNT_JSON`, enables push.
- `OPENAI_API_KEY` / `CREWAI_BROKER_URL`, enables AI chat agents.

## 6. Health & verification

- Gateway upstream health: `GET /health/upstream`
- Per-service: `GET /health` on any service container.

If a service is unhealthy at boot, check its logs (`docker compose logs <service>`);
most failures are missing env (e.g. `JWT_SECRET`) or the PostGIS migration not having
run (ensure `./infrastructure/databases/postgres/migrations` is mounted).
