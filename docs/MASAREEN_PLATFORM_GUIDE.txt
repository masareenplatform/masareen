MASAREEN PLATFORM GUIDE
=======================

Last updated: 2026-10-30
Production site: https://masareen.com
Mobile app: MASAREEN (Flutter)
Backend: Cloudflare Worker + D1 + R2

1. WHAT MASAREEN IS
-------------------
MASAREEN is an impact and professional network for verified public work. It
combines a social feed, professional profiles, programs and projects, learning
courses, opportunities, field evidence, sports organisations, messaging,
notifications, a coin wallet, paid plans, and an ads manager.

The platform is Arabic-first and bilingual (English/Arabic). The mobile client
is the primary product; the landing site is static and served from R2. All API
traffic is served by one Cloudflare Worker under /api/*.

3. ARCHITECTURE
---------------
Client
  Flutter mobile app and static landing page.

Edge API
  Cloudflare Worker named "masareen".
  Routes: masareen.com/api/* and www.masareen.com/api/*.
  The same Worker handles auth, social, professional, commerce, ads and admin.

Storage
  D1 database "masareen" for all relational data.
  R2 bucket "masareen-landing" for media and the static site.
  Media is public through the masareen.com custom domain under /media/*.

Email
  Resend for verification, password reset, contact messages and notifications.
  MAIL_FROM uses the verified notify.masareen.com domain.

No Durable Objects and no external queue are required. Near-real-time behaviour
is implemented with short polling plus an 8-second live interaction endpoint.

8. AUTHENTICATION AND SESSIONS
------------------------------
Supported sign-in:
  - Email and password
  - Google Sign-In
  - Session cookie for browser clients
  - Bearer access token for mobile clients

Flows:
  - Email registration with verification token
  - Login and logout
  - Password reset by email
  - Google ID token verification
  - Session rotation and tamper detection

Admin access is controlled by ADMIN_EMAILS. Admin routes return 401 when the
caller is not signed in and 403 when the caller is signed in but not an admin.

9. CORE DOMAINS
---------------
9.1 Social feed
  Posts support text, media galleries, video, files, links, location, kind,
  SDG tag, impact value and visibility.
  Actions: like, comment, share, bookmark, hide, report, vote on impact.
  Feed modes: for_you, following, latest, impact.
  Ranking is deterministic: score, then created_at, then id.
  Pagination does not wrap. An offset at or beyond the end returns an empty
  list. Clients should stop loading when the returned page is shorter than the
  requested limit.

9.2 Impact and confidence
  Post impact is recomputed after likes, comments, shares, unlikes and comment
  deletion.
  Confidence is derived from vote count, author verification and engagement:
    clamp(40 + min(30, votes * 6) + (verified ? 16 : 0)
          + min(12, engagement * 12), 5, 99)
  The previous confidence value is not fed back into the calculation, avoiding
  a self-reinforcing score.

9.3 Professional profiles
  Personnel profiles support:
    headline, summary, mission, beat, expertise, specializations, skills,
    languages, education, experience, certificates, awards, publications,
    memberships, employment status, availability, website, social links,
    coverage regions, coverage hours and visibility.
  Visibility values: PUBLIC, CONNECTIONS, PRIVATE.
  Users can edit their own profile; admins can edit any profile.
  Profiles aggregate impact, trust, reach, engagement, media value, badges and
  the Professional Merit Score (PMS).

9.4 Programs, projects and courses
  Programs contain tasks and linked projects. Users can enroll and complete
  tasks. Projects support membership. Courses support enrollment and progress.
  Completion feeds verification and professional scoring.

9.5 Opportunities
  Organisations publish opportunities with type, location, deadline and tags.
  Members apply once per opportunity. Matching notifications are deduplicated.

9.6 Verification and evidence
  Evidence records attach proof to reports and submissions. Submission review
  moves work through verification states. Verified work contributes to the
  impact passport and professional score.

9.7 Sports
  Sports organisations, squads, results, player careers and showcases are
  supported through dedicated tables and routes.

9.8 Messaging and notifications
  Conversations support direct messages, unread counts, blocking and reporting.
  Notifications cover social actions, follows, messages, opportunities,
  reports and system events.
  In-app polling:
    conversations list: 15 seconds
    open chat thread: 5 seconds
    notification polling: 15 seconds
    live post counters: 8 seconds

9.9 Live interactions and presence
  GET /api/v1/live/interactions?post_ids=1,2,3
  Auth required. Maximum 60 post IDs.
  Returns:
    posts[] with likes, comments, shares, impact_value, confidence_score,
    latest_comment_id, liked_by_me and bookmarked_by_me
    unread_messages
    unread_notifications
    server_time

  The mobile LiveSyncService watches visible feed posts and the open post
  detail screen. It polls every 8 seconds, pauses when the app is not resumed,
  and ignores empty watch sets. Message and notification counts are returned by
  the same endpoint.

  Authenticated requests update users.last_active_at at most once every five
  minutes. Admin DAU/WAU/MAU metrics union login events with last_active_at.

9.10 GPS records
  POST /api/v1/gps/records
  GET  /api/v1/gps/records
  Auth required.
  POST accepts latitude, longitude and optional accuracy, altitude, speed,
  heading and captured_at. Coordinates are validated. GET returns the latest
  100 records for the current user.
  The mobile post composer records a GPS point when the user attaches a
  location, in addition to embedding the coordinates in the post.
  Settings > Privacy > Location history shows the latest 100 points with
  timestamps and accuracy; tapping a row opens it in the device maps app.

9.11 Wallet, coins and plans
  Every user has a coin wallet.
  The daily reward is set by the server (default 10 MRC, one claim per
  account per day). A client may send an amount for backward compatibility,
  but the Worker ignores it, so the reward cannot be inflated from the app.
  Operators can override it with the optional DAILY_REWARD_MRC Worker var
  (capped at 500). Wallet responses include daily_reward, claimed_today and
  last_claim_at so clients display the real state.
  Pro plans:
    monthly: 500 MRC for 30 days
    yearly: 4500 MRC for 365 days
  Coin transfers debit the sender and credit the recipient atomically.
  The wallet screen supports claiming daily rewards and transferring coins.
  The server enforces caps even if a client submits a different amount.

9.12 Payments
  Paymob is integrated for card payments and subscriptions.
  Until Paymob secrets are configured, /api/v1/payments/psp/status reports
  enabled=false and production checkout is unavailable.
  Wallet and coin flows work without Paymob.

9.13 Ads manager
  Advertisers create campaigns with budget, schedule, targeting and creatives.
  Limits:
    minimum budget: 50 MRC
    maximum budget: 100000 MRC
    maximum 5 creatives per campaign
    maximum 3 active or paused campaigns per user
    daily impression cap: 8 per user
    campaign frequency cap: 12 hours
    maximum 3 feed ads per feed session
  Pricing:
    impression: 0.2 MRC
    click: 2 MRC
  Activation debits the full budget. Budget edits debit or refund the
  difference. Completing or rejecting a campaign refunds funded minus spent.
  Events consume reserved budget and auto-complete the campaign when exhausted.
  The feed excludes the advertiser's own campaigns and enforces frequency caps.

9.14 Admin
  Admin screens cover users, reports, payments, inquiries, ads, testers and
  platform analytics.
  /api/v1/admin/stats returns nested totals, series, top_campaigns,
  recent_reports, recent_payments, recent_inquiries and recent_users.
  /api/v1/admin/reports returns an array by default and {items, counts} when
  called with ?with_counts=1. Count keys are lowercase.

9.15 Universities, research and entity links
  GET /api/v1/institutions?q=&type= lists universities, government bodies,
  organisations, media and sports entities with content counts.
  GET /api/v1/users/:id/institution returns the profile plus linked courses,
  events (with funding), programs, projects, opportunities and research stages.
  UNIVERSITY and RESEARCHER are valid user roles alongside INSTITUTION.
  GET/POST /api/v1/research/stages publishes a stage (IDEA, LITERATURE,
  METHODOLOGY, FIELDWORK, ANALYSIS, RESULTS, PUBLISHED). Publishing creates a
  RESEARCH_STAGE feed post, notifies followers and links the stage to its
  institution. Create is limited to academic/researcher/university roles.
  GET/POST/DELETE /api/v1/entity-links connects any two entities
  (user, course, event, program, project, opportunity, research_stage, post)
  with an ownership-checked relation such as TEACHES, HOSTS or PARTNER.
  POST /api/v1/events/:id/fund moves MRC from the supporter wallet to the event
  author and increments funding_raised. Final-year projects set project_type
  (UNIVERSITY, GRADUATION, RESEARCH, SCHOOL) and institution_id, then appear on
  that institution's profile.
  Mobile: Universities screen + drawer entries, Research hub, rich institution
  profiles with follow, funding, linked content and an owner "Connect content"
  action.

11. MOBILE APP
--------------
Main navigation: Home, Explore, Create, Courses, Profile.

Navigation shell (2026-10-30):
  The five destinations live in a persistent floating bottom bar with visible
  labels and the member's avatar on the Profile item. Each tab owns a nested
  Navigator, so screens opened inside a tab (messages, wallet, settings,
  profiles, post detail, ...) keep the bar visible.
  A sliding end drawer, opened from the menu icon or an edge swipe, contains
  the full menu: account, platform, finance, administration (admins) and
  system actions (settings, theme, language, sign out).
  Back pops the active tab stack first; back on the Home root asks for a second
  press before exiting.
Feature screens include feed, post detail, search, messages, notifications,
professional profile, organisation profiles, government profiles, institution
profiles, news media profiles, sports profiles, player showcase, programs,
projects, courses, opportunities, verification, wallet, payments, pro plans,
ads manager, settings, location history, admin and tester management.

Key services:
  PollingService          notification polling and local notifications
  LiveSyncService         visible post counters, unread counts, 8-second poll
  NotificationService     local notification presentation

Share and export:
  Profile share copies https://masareen.com/u/{userId}
  Post share copies https://masareen.com/p/{postId}
  Professional profile export copies a formatted text summary.
  These actions use the system clipboard and show a confirmation snackbar.

OTA UPDATES (outside the stores)
--------------------------------
Update manifest:
  GET /api/app/version is public and returns:
    android: version, build, url, size, etag, notes
    ios: version, build, url, notes
    minimumBuild
    ota: { provider: "shorebird", appId }
  Bump APP_ANDROID_VERSION / APP_ANDROID_BUILD / APP_MIN_BUILD in
  cloudflare/wrangler.toml when the APK is replaced. The android-apk workflow
  uploads it to R2 at downloads/masareen.apk and can update the vars.

Android (sideloaded APK):
  The app checks the manifest on launch and from Menu > Check for updates.
  When a newer build exists it downloads the APK from R2, asks for the
  "install unknown apps" permission once, and opens the Android installer.
  Android updates the app in place; data is preserved. The app requests the
  REQUEST_INSTALL_PACKAGES permission (see tool/patch_android.py).

iOS:
  Native builds cannot self-install outside the App Store. The app can open the
  download/TestFlight page. For Dart-only changes, use Shorebird code push:
    cd apps/mobile
    npm i -g shorebird
    shorebird login
    shorebird init --force        # replaces the placeholder app id
    shorebird release ios         # signed/TestFlight build
    shorebird patch ios           # Dart-only OTA patch
  Android can use the same Shorebird patches instead of, or in addition to,
  the APK updater. Native/plugin/permission changes always need a new build.

16. SECURITY AND PRIVACY
------------------------

  - Session cookies are signed and tamper-checked.
